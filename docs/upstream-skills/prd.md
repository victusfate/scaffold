# PRD: upstream-skills

## Problem

Scaffold's flow stops at "tests pass and the reviewers are satisfied." Three gaps remain:

1. Nothing exercises the running app. AGENTS.md defines done as reachable from a
   user entry point, but no skill checks that by driving the entry point.
2. There is no debugging method. `/create-pr` Step 2 says "diagnose" with no
   procedure, and agents fall into guess-and-patch loops.
3. Prose output (PR bodies, docs, design artifacts) is unchecked, though AGENTS.md
   bans self-labelling filler.

## Solution

Three prompt skills, adapted from MIT upstreams (see `design.md`), registered on
every harness and wired into `/feature-chain`, `/create-pr`, and `/tdd`.

## User stories

- As a user running `/feature-chain` on a UI or API feature, I get a `/qa` pass
  that drives the real entry point and fixes what it finds before review.
- As an agent whose test or CI step fails unexpectedly, `/investigate` gives me a
  root-cause procedure and a hard stop after three failed fixes.
- As a user opening a PR, the body has already been checked for slop patterns.
- As a user, I can run `/qa`, `/investigate`, or `/deslop <file>` on their own.

| `package.json` | Add the three tests to `npm test` |

## Testing decisions

Prompt skills are tested the way `council` is (`scripts/test-council-skill.sh`):
a shell test asserts that the files exist, the core mechanics and guards are present
in the canonical body, the wrappers include it, and the manifest and RESOLVER list
it. Each test also asserts the upstream credit line and the flow wiring in the
calling skill, so removing the wiring fails the suite. `check-resolvable.ts --strict`
and `update-skills-doc.ts --check` must stay green.

## Out of scope

Other skills from the list (taste-skill, UI/UX Pro Max, caveman, last30days,
slides, marketing, legal, brag). A Playwright driver script for `/qa`.
